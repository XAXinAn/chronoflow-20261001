# 上架合规检查清单（每个版本都要跑）

> **适用场景**：每次开发完一个新版本、准备提交应用宝（或任何应用商店）之前，
> 以及每次改动登录 / 权限 / 数据收集 / 第三方 SDK / 隐私政策文本之后。
>
> **依据**：应用宝开放平台《[隐私政策提交内容及审核规范](https://wikinew.open.qq.com/index.html#/iwiki/875339652)》
> （仓库内离线全文：26 页扫描件，含「一、隐私政策提交规范」「二、隐私政策内容规范」
> 「三、个人信息标准表述参考」「四、隐私检测范围及审核说明」）。
>
> **怎么跑**：
>
> ```bash
> python3 scripts/check_compliance.py      # 自动项，逐条打印「通过 / 未通过 + 怎么修」
> ```
>
> 自动项是**门禁**：CI 里会跑，未通过即构建失败。人工项（表格里标「人工」的）需要真的
> 点一遍 App / 打开一次链接确认，不能只看代码。

---

## A. 隐私政策提交规范（规范 §一）

| # | 要求 | 本项目怎么满足 | 怎么验证 |
| --- | --- | --- | --- |
| A1 | 提交的隐私政策**链接内容**必须与 **App 内**的隐私政策**完全一致** | 只有一份 Markdown（`docs/legal/*.md`）；后端渲染成 HTML 挂 `/api/v1/legal/{doc}`；**App 用 WebView 打开同一个地址**，天然逐字一致 | 自动：`legal-single-source`；人工：打开 `https://<域名>/api/v1/legal/privacy-policy` 与 App 内「我的 → 隐私与合规 → 隐私政策」比对 |
| A2 | 链接必须是**公开可访问、无需登录、无需点击、无需跳转**的静态页面 | `/api/v1/legal/**` 在 `SecurityConfig` 里 `permitAll`，返回 `text/html; charset=utf-8`，页面内无脚本、无跳转 | 自动：`legal-endpoints-public`、`legal-html-no-script`；人工：无痕窗口直接打开 |
| A3 | 链接不能是博客 / 微博 / GitHub / 云笔记，也不能是 Word、图片等文件格式 | 由我们自己的服务器直接渲染 HTML | 人工：确认提交的是 `https://<域名>/api/v1/legal/privacy-policy` |
| A4 | App 内展示内容与链接一致，更新时同步 | 同上，同源渲染，改文件即同时生效，不需要发版 | 自动：`legal-single-source` |

## B. 隐私政策内容规范（规范 §二）

| # | 要求 | 对应条款 | 怎么验证 |
| --- | --- | --- | --- |
| B1 | 隐私政策必须**单独成文**，不能作为用户协议的一部分 | 规范 §2.1 | 自动：`policy-standalone` |
| B2 | 必须有**明确的运营主体公司信息**，且与应用「运营方 / 研发方」一致 | 规范 §2.2 | 自动：`policy-subject-declared`（存在主体段落）；**人工：把 `【待替换：…】` 换成营业执照主体名称** |
| B3 | 使用集团或第三方隐私政策时，须说明关联关系 | 规范 §2.2③ | 不适用（本应用无第三方隐私政策）；改用时必须补 |
| B4 | 敏感个人信息须以**显著方式**（加粗 / 下划线）标识 | 规范 §2.3 | 自动：`policy-sensitive-marked`；人工：确认加粗在 App 内同样生效 |
| B5 | 收集使用规则变更时，及时告知并在取得同意后处理 | 规范 §2.4 | 人工：发版说明 + App 内弹窗文案 |
| B6 | 不得强制要求同意超范围或与服务场景无关的处理 | 规范 §2.5 | 自动：`no-forced-consent`；人工：拒绝权限后逐个功能试点 |
| B7 | **SDK / 个人信息超链接名称必须含关键词**（如《第三方SDK名称信息》），不能是《附件》《详情》 | 规范 §2.6 | 自动：`no-vague-link-label` |
| B8 | **账号注销**：隐私政策内写明注销步骤流程，且 App 内有对应注销功能按钮；承诺时限不超过 15 个工作日 | 规范 §2.7 | 自动：`policy-deletion-steps`、`app-deletion-entry`、`api-deletion-endpoint`；人工：真的走一遍注销 |
| B9 | 含**个性化 / 定向推送**说明时，必须有对应的关闭开关 | 规范 §2.8 | 自动：`policy-personalized-push-declared`；本项目**不做个性化推荐**，已明示不需要开关；若将来上线，必须加开关 |
| B10 | 儿童（14 周岁以下）：单独明示儿童隐私政策并取得监护人同意 | 规范 §2.8-3 | 自动：`children-policy-exists`、`first-launch-shows-children-notice` |
| B11 | App 二级菜单展示**已收集个人信息清单**与**与第三方共享个人信息清单** | 规范 §2.8-4 | 自动：`info-lists-exist`、`app-info-list-entries` |
| B12 | 申请身份证号等敏感信息须告知目的 | 规范 §2.8-5 | 不适用（本应用不收集身份证号） |
| B13 | 隐私政策结构：导言 / 收集使用 / Cookie / 共享转让披露 / 保护 / 存储 / 用户权利 / 未成年人 / 其他 / 变更 | 规范 §二-1 | 自动：`policy-ten-sections` |
| B14 | 说明信息存储的地理区域、保留时间、用户画像用途 | 规范 §二-1 | 自动：`policy-storage-and-retention` |

## C. 个人信息表述规范（规范 §三）

| # | 要求 | 怎么验证 |
| --- | --- | --- |
| C1 | 使用规范化的信息名称（如「手机号码」而不是「电话」；「地理位置」而不是「定位」） | 自动：`standard-wording` |
| C2 | 同意 / 拒绝使用规范表述（「同意」「拒绝」） | 自动：`no-vague-link-label`、`consent-buttons-explicit` |

## D. 隐私检测范围（规范 §四，云手机动态检测的实际检测项）

| # | 检测项 | 要求 | 怎么验证 |
| --- | --- | --- | --- |
| D1 | 违规收集 | **首次进入 App 必须有隐私政策弹窗**，征求用户阅读并同意 | 自动：`first-launch-consent-gate`；人工：清数据后冷启动 |
| D2 | 违规收集 | 同意按钮清晰、**不得默认同意** | 自动：`no-default-consent`、`consent-not-premarked` |
| D3 | 违规收集 | 同意前不得提前收集个人信息 | 自动：`first-launch-consent-gate`（弹窗先于任何网络请求）；人工：抓包确认冷启动无业务请求 |
| D4 | 超范围收集 | 不得收集与服务无关的信息，不得超频次 | 自动：`info-lists-exist`；人工：对照《已收集个人信息清单》逐项核对 |
| D5 | 违规使用 | 不得私自向其他应用或服务器发送 / 共享个人信息 | 自动：`shared-list-exists`；人工：核对《与第三方共享个人信息清单》 |
| D6 | 权限 | 用户**拒绝权限后不得强制退出或关闭 App**；不得提前申请与业务无关的权限；不得频繁弹窗 | 自动：`permission-rationale`；人工：逐条拒绝后确认 App 仍可用 |
| D7 | 自启动 | 不得静默自启动或关联启动第三方 App | 人工：Android 自启动管理里确认无自启动行为 |
| D8 | 定向推送 | 提供关闭开关且**开关名称须显著区分**（如「个性化推荐」） | 本项目不提供该功能（见 B9） |
| D9 | 隐私政策常驻入口 | 从**主界面到隐私政策入口不得超过 4 步** | 自动：`app-policy-entry-depth`；人工：数一下点击次数 |
| D10 | 基本功能 | 拒绝提供非必要个人信息时，**不得影响基本功能** | 人工：关闭相册 / 定位后仍能新建日程与待办 |

## D+. 本轮新增（2026-09-27：小安接入通义千问 + 语音输入）

接第三方模型是**新的信息收集点**，也是最容易「功能上了、清单没跟上」的一类改动。
下面这条自动检查专门盯它（`assistant-disclosure`）：

| # | 要求 | 怎么验证 |
| --- | --- | --- |
| E1 | 小安会把**您输入 / 说出的内容**与**为回答而查询到的日程文本**发给模型服务商 | 自动：`assistant-disclosure`（隐私政策 §4.1 共享、§9.1 第三方 SDK 目录、《与第三方共享个人信息清单》三处都要有百炼 / 通义千问） |
| E2 | 语音用于转写，**转写完成后音频立即丢弃、不保存录音** | 自动：`assistant-disclosure`（隐私政策 §2 收集清单、§6.2 存储期限、《已收集个人信息清单》三处一致）；人工：抓包确认请求里没有音频回传 |
| E3 | 麦克风要**先说明用途再申请**，拒绝后仍可直接打字 | 自动：`assistant-disclosure` + `permission-rationale`；人工：拒绝麦克风后确认还能发消息 |
| E4 | 声明的权限与实际一致（不能一边用麦克风、一边写「不申请麦克风」） | 自动：`assistant-disclosure` 会拦住旧表述；人工：对照 `app.json` 的权限与插件配置 |

**人工补充确认**：小安的**写操作必须由用户在卡片上点确认**才会真正写入日程；
组织下发的日程对它只读。这条由端到端用例覆盖（`AgentModuleTest`：动作卡片不落库）。

## E. 版本发布前的固定动作

1. 跑 `python3 scripts/check_compliance.py`，必须全绿；
2. 跑后端 / App / web-admin 的测试（见 `AGENTS.md`）；
3. 在真实设备上冷启动一次，确认首启弹窗出现、不同意则不进入登录页；
4. 在登录页确认复选框**默认未勾选**，未勾选时「登录 / 注册」不可点；
5. 打开 `https://<域名>/api/v1/legal/privacy-policy`，与 App 内页面比对；
6. 走一遍「我的 → 隐私与合规 → 账号注销」，确认注销后原手机号可重新注册；
7. 若本版本新增了任何**第三方 SDK / 新权限 / 新的信息收集点**，
   同步更新 `docs/legal/*.md` 的清单与隐私政策，再重新跑第 1 步。
