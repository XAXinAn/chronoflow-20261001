## 1. 定位（华为等无 Google 服务的机型）　【P0，本轮重点】

**背景**：以前用华为这类没有 Google 服务的手机，「授权了定位也取不到位置」。
原因是旧实现走 Google 的融合定位（GMS），这类机型上必然失败。本版改成直读系统自带的
`LocationManager`，不依赖 GMS。

### 操作步骤

1. 进 **日历** 标签 → 右下角 **＋ 新建** 日程（或点开一条已有日程点编辑）。
2. 找到 **「地点」** 字段，**点进去**。
3. 第一次进这个页面，会先弹**我们自己的用途说明**，点确认后弹出系统的
   **「要允许时纪流访问您的位置吗？」** → 选 **「使用应用时允许」**。
4. 观察地图落在哪里，以及右下角的定位按钮。
5. 如果第一次没落对，点**右下角的定位图标**手动重试一次。

### 通过标准

- ✅ **地图中心落在你当前所在的位置**（不是固定停在北京这类默认坐标），下方地址栏显示你附近的地名。
- ✅ 点右下角定位图标能反复重定位，不会卡着不动。
- ✅ **拒绝**授权时，页面不闪退、不退出：给一句「未授权定位，已打开默认位置；可点右下角图标重试，
  或直接搜索地点」，并且**仍然可以搜索地点手动选**（这是规范要求，不能因为拒权限就不让用）。

### 不通过时怎么报

先看清楚**界面给了哪一句提示**，它已经把原因分成了三类，把原话抄下来：

| 界面提示（大意） | 说明 | 责任方 |
| --- | --- | --- |
| 「未授权定位…」「未授予定位权限…」 | 系统权限没给 | 重新到系统设置里给权限 |
| 「暂时取不到当前位置，已打开默认位置…」 | 有权限但拿不到坐标（服务没开 / 室内信号差 / 原生模块报错） | **要报**，见下 |
| 「定位失败，请稍后重试…」 | 同上，手动点的那次失败 | **要报** |

如果落在默认位置、且给的是后两类提示 —— 这就是本轮要抓的 bug。**证据**：

1. 手机型号 + Android 版本 + 系统「设置 → 位置信息」是否开启 + 是否给了「使用应用时允许」；
2. 有没有**换一台有 Google 服务的手机，同一账号同样操作能不能定位成功**（能成功 = 问题只在无 GMS 机型，
   正好是本轮修复目标）；
3. 电脑上抓一份日志，命令见 **附录 A**。

> ⚠️ **一个如实说明**：定位失败的**内部原因码**（权限 / 服务未开 / 超时）目前**没有写进日志**，
> 界面上只体现为上面那几句文案。所以**不要去找日志里的 `E_LOCATION_*`**（找不到是正常的）。
> 如果这轮想精确区分失败原因，可以让开发在失败分支补一行日志再出一版——目前以界面表现 + 对照机为准。

## 3. 提醒方式：改成**按日程**配置　【P0，本轮重点】

**背景（你的反馈）**：以前「提醒声音」是 App 里的**全局**设置，改一次影响所有日程——
而你要的是「这条日程要静音、那条要闹钟」。这一版把它下沉到**每条日程/待办**上，
三档也改成 **静音 / 消息提醒 / 闹钟**（不是「系统提示音」那种说法）。
**不做推送**（服务端推送链路没接通，见附录 C）。

### 3.1 先看两处设置

1. 进 **我的 → 偏好**（入口副标题是「深色模式、到点提醒」）。
2. 找到 **「到点提醒」** 总开关：**默认应该是关**，关着时说明写着 **「已关闭，到点不会提醒」**。
   把它**打开**。
3. 同一页有一行 **「默认提醒方式」**：三档 **静音 / 消息 / 闹钟**。
   它是**新建日程/待办时的默认值**（不再是全局开关），副标题会写「新建日程 / 待办时用它，可逐条改」。

> 顺带验一处文案联动：**总开关还关着**的时候，去 日历 → ＋ 新建 → 设一个**提醒提前量**，
> 提醒页底部应出现红字 **「到点提醒总开关当前是关闭的，这样设置不会响…」**。

### 3.2 核心：每条日程单独设（本轮重点）

1. **日历 → ＋ 新建**，标题随便写，时间设**今天稍后**（要能等到）。
2. 点 **「提醒」** → 页面下半部分会出现 **「提醒方式」**：**静音 / 消息提醒 / 闹钟**，
   下面还有一行说明当前选中的档是什么意思。
3. 选 **闹钟**，挑一个提前量（比如「到点」），保存。
4. 再建**第二条**日程，这次「提醒」里选 **静音**，同样设一个到点提醒。
5. 两条都到点后对比：**一条按闹钟响、一条不响**（通知栏都出现）。

**这一条才是本轮的验收核心**：以前改档位是全局的，两条日程不可能一个响一个不响。

### 3.3 三档各自的表现

| 档位 | 期望 |
| --- | --- |
| **静音** | 通知栏**出现**这条提醒，但**不响、不震** |
| **消息提醒** | 像收到消息一样：**响一声并震动**（不是「放一段提示音」，是普通消息通知那种打扰级别） |
| **闹钟** | 按**闹钟音量**响（明显更大更长），会尝试绕过免打扰 |

### 3.4 顺带验「改了立刻生效」

1. 用「消息提醒」档新建一条 **3 分钟后**的提醒；
2. **不改这条日程**，只去 我的 → 偏好 把「默认提醒方式」切成 **静音**；
3. 等那条到点 —— **应该仍然按「消息提醒」响**（因为它是这条日程自己的档位，不受默认值影响）。

> 如果你期望的是「改默认值能影响已有日程」，那说明理解与本实现不同，告诉我我再调。

### 通过标准与已知限制

- ✅ 两条日程可以一个静音、一个响；编辑页把这一条改档位后**保存即可生效**。
- ✅ 「我的 → 偏好」里那一档只影响**新建**的日程。
- ⚠️ **闹钟档不保证一定响**：部分国产机型的省电策略会拦掉后台提醒，**这是系统限制，不是 bug**。
  测之前请先把 App 加进「自启动 / 后台运行」白名单，再下结论。
- ⚠️ 如果**都完全不响**：先确认第 0.4 步的通知权限与后台白名单；确认无误后就是真问题，要报。

## 3.5 认证 / 绑邮箱后，返回要立刻刷新　【P0，本轮修复】

**背景（你的反馈）**：实名认证通过、或邮箱绑定成功后，回到「我的」和「账号与安全」还显示
「未实名 / 未绑定」，要重进一次才对。根因是那两屏只在**首次挂载**时拉一次状态，

3. 再返回一层到「我的」页，看**名字下方那一行**。

### 通过标准

- ✅ 两个地方**当场**就显示新邮箱，不需要退出重进。
- ✅ 实名认证同理：认证通过返回后，「实名认证」那一行立刻变成「已实名 · 张\*\*」。

> 反例（本轮之前的 bug）：两处都还写着「未绑定邮箱 / 未认证」，杀进程重开才变。

## 4. 换手机号时可以不用旧号（走邮箱验证码）　【P0】

**背景**：换绑手机号一直要求「旧号验证码 + 新号验证码」两个。旧号丢了 / 停用的人就没法换。
本版新增：把「本人验证」**二选一**，可以用**已绑定邮箱**的验证码替代旧号验证码。

### 前提

账号得**已经绑定并验证过邮箱**。没绑的话，切到「邮箱验证码」时会提示
「旧手机号不能用了？账号还没有绑定邮箱，无法用邮箱验证。请先在「我的 → 账号与安全 → 邮箱」绑定并验证一个邮箱，
再回来换号。」——这是**正常的**，不是 bug。

### 操作步骤

**第一步：先绑邮箱**

1. **我的 → 账号与安全 → 邮箱**；
2. 填邮箱 → 点发验证码 → 去收件箱找（**先翻垃圾箱**，发件人 `noreply@xaxinan.top`）；
3. 填码提交，应显示绑定成功。

**第二步：用邮箱验证码换号**

4. 回到 **我的 → 账号与安全 → 手机号**（或页头那行「手机号 · 实名 · 邮箱」）→ 点 **「切换手机号」**；
5. 页面顶部写着「当前手机号：138\*\*\*\*1111。换绑需要两个验证码：新号一个，外加一次『本人验证』」。
6. 填 **新手机号** → 点「获取验证码」→ 收新号短信；
7. 找到 **「本人验证」**，把它从默认的「旧号验证码」**切成「邮箱验证码」**；
8. 点发邮箱验证码 → 收邮件 → 填进去；
9. 提交。

### 通过标准

- ✅ 换绑成功；回到「账号与安全」显示**新号（脱敏）**。
- ✅ 用**旧号**登录不再能进这个账号（应提示手机号不存在 / 需新号）。
- ✅ 两个验证码按钮**各自倒计时、互不影响**。

### 边界（顺手验一下，能挡住盗号）

- ⚠️ **两个码都填 / 都不填** → 服务端应直接**拒绝**（这是有意设计，避免含糊）。
- ⚠️ 邮箱换号用的验证码，**不能**拿绑定邮箱时收到的那个码来顶替（两套场景码是分开的）。
- ⚠️ 未绑邮箱却切到「邮箱验证码」→ 应给上面那句提示，而不是静默失败。

## 5. 成员批量导入（100+ 行）　【P0】

**背景**：以前「批量导入一直没反应 / 一直失败」。原因有三：后端把异步任务派得太早（批次永远停在处理中）、
模板示例行与表头错列、前端提交后不轮询所以看不到进度。本版三处都修了。

### 操作步骤

1. 用**组织管理员账号**登录后台 `http://60.205.142.205:8080/`（先 **Ctrl+F5 硬刷新**）；
2. 进 **成员管理 → 批量导入**；
3. 点 **「下载模板」**，打开看一眼：**表头是「姓名 / 唯一识别 ID / 部门路径 / 角色」，
   第二行的示例数据应该正好对得上这四列**（以前示例里塞了手机号、邮箱，照填必然错列）；
4. 准备一份**真实表格，100 行以上**，部门路径用中文（如 `技术中心/后端组`）；
5. 上传 → 提交，**盯着弹窗**。

### 通过标准

- ✅ 提交后出现**进度条**，文案形如「正在导入：已处理 37 / 120 行」，
  并在跑了一小会儿后出现「预计还需约 xx 秒 / 分钟」。
- ✅ 进度条**会动**（数字在涨），不是一直停在 0 / 一直转圈。
- ✅ 跑完状态变成 **「全部成功」或「部分失败」**，并自动**刷新下方成员列表**。
- ✅ 失败的行**有明确原因**（学号重复、部门不存在…），可以**下载失败明细**。
- ✅ 再单独测一次：**直接用下载的模板（连示例行一起）上传**，应该至少成功 1 行。

### 已知行为（不是 bug）

- 前 1.5 秒**不显示预计时间**是故意的（样本太少算出来的数字没意义）。
- 轮询最长跑 **10 分钟**；超过会停下并提示「批次仍在处理中，已停止自动刷新，可点『刷新进度』查看最新状态」，
  弹窗里有 **「刷新进度」** 按钮。

### 不通过时怎么报

给出：文件行数、**十几秒后的进度截图**、失败明细（如果有）、用的哪个组织。

## 6. 上传图片识别日程（历史遗留，一直没在真机验过）　【P1】

**背景**：这条链路（本地 OCR → 云端解析 → 确认页）代码早就通了，但**识别效果从来没在真机上验过**。
端侧识别用的是 PaddleOCR PP-OCRv4（**图片不上传，全程在手机本地识别**）。

### 操作步骤

1. 进 **日历** → 月历下方 **「点此上传图片，一键添加日程」**；
2. 选来源（**相册 / 拍照**）→ 选一张**真实的中文通知 / 行程单 / 课程表**照片；
3. 等它本地识别出文字、再把文字发给服务端解析 → 进**确认页**；
4. **点确认页里的任意一条**（整张卡片都可以点）→ 应进入**详情编辑页**，在那一页里改
   标题 / 日期 / **时间** / 地点 / 重复 / 提醒；改完返回，确认页上那条跟着更新。
5. 全部条目都有日期后，底部「添加 N 条日程」才可点。

> **本轮改动（你的反馈）**：确认页原来点那行「日期 · 时间」会弹出**日期**滚轮
> （看着像时间、其实只能改日期，容易点错）。现在**去掉了这个弹层**——
> 统一「点整条 → 进详情页改」，那里能改的更多。
> 请重点看：点日期/时间那一行，是否进详情页（而不是又弹出一个小选择层）。

### 要记录的两件事

| 记什么 | 怎么记 |
| --- | --- |
| **准确率** | 识别出来的文字与照片原文对得上多少（错字 / 漏字 / 顺序乱），最好截图对比 |
| **耗时** | 第一次（要加载模型，会慢）与之后几次各多少秒。可以参考日志里的埋点，见下 |

**日志里有现成的耗时埋点**（这条链路是打了日志的）：

```
[vision] OCR(...) 得到 N 字：...
[vision] PaddleOCR 端侧：检测 xxms（N 行，方向分类 xxms）→ 识别 xxms（N 行）→ 合计 xxms
```

抓日志的命令见 **附录 A**。

### 已知行为（不是 bug）

- 没识别到**时间** → 备注开头会写「未识别到具体时间，已默认填 09:00，请核对」；
- 没识别到**日期** → 那条标红「请选择日期」，需要你补；
- 第一次比后面几次慢（要先加载本地模型）。
- 如果提示「端侧识别需要开发版构建 / 本地识别库没就绪」——**要报**，把提示原文截图。

## 附录 A：抓日志（Windows + USB）

只在「定位失败要取证」「想看 OCR 耗时」「App 闪退」这三处才需要。

**准备**：手机开「开发者选项 → USB 调试」，用数据线连电脑，弹窗选「允许」。

在 **cmd** 里（adb 在 Android SDK 里；本项目文档里的固定路径如下）：

```bat
set ADB=C:\Users\jiang\AppData\Local\Android\Sdk\platform-tools\adb.exe

:: 1) 确认设备已连上（状态应显示 device）
%ADB% devices

:: 2) 清空旧日志，让接下来抓到的干净
%ADB% logcat -c

:: 3) 现在去手机上复现问题（比如点定位）

%ADB% logcat -d -b crash > %USERPROFILE%\Desktop\crash.txt
```

把桌面生成的 `crash.txt` / `js.txt` 连同**复现时间点**一起发过来。

## 附录 C：已知限制（**先别当 bug 报**）

1. **iOS 还没有安装包**（要 macOS 构建），目前只有 Android。
2. **安装包约 165MB**：含本地 OCR 的推理运行时与模型（图片不出手机就是靠它）。
3. **闹钟档不保证一定响**：国产机型的省电策略可能拦后台提醒，属系统限制。
4. **邮件验证码可能进垃圾箱**（发信域名 `xaxinan.top`）。
5. **实名认证**可能提示「暂不可用 / 场景类型不匹配」——阿里云场景配置问题，开发在跟进。
6. **管理后台不是普通用户功能**，地址 `http://60.205.142.205:8080/`。
7. **定位失败的内部原因码目前不落日志**（见第 1 项的说明），以界面提示 + 对照机为准。
8. **不做推送提醒**：App 端从没上报过推送设备标识，服务端推送链路是断的；到点提醒一律走
   **手机本地通知**。所以「提醒方式」里没有「推送」这一项。
9. **「图片直传云端大模型」已经试过、决定不用**（2026-10-14）：把图片交给云端 qwen-vl 识别，
   质量尚可但**端到端要 7–8 秒**（关思考也没稳定变快），明显慢于端侧 OCR；而且与
   「图片不出手机」的承诺冲突。**所以正式路径仍是端侧 OCR**，这条只是个可配置的试验口子（默认关闭）。
